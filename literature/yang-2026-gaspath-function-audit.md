## Two production defects take priority

1. **enhancedROC clinical impact conflates prevalence, decision threshold and population workload.** `.a.yaml:357` promises clinical impact at supplied prevalence, but `.b.R:5471` uses prevalence as a risk threshold clamped to [0.01,0.99], computes TP/FP/FN/TN on observed rows (`:5474–5477`), and calls rounded inverse net benefit NNT (`:5484–5490`). Decision rows use hardcoded cutoffs 0.1,0.2,0.3 plus that threshold (`:5512`), **not `customCutoffs`**; PPV/NPV remain raw sample fractions (`:5520–5532`). The curve is also observed counts/n*1000 (`:5571–5572`) on a 0.01–0.99 grid (`:5554`). Notice `:5417` tells users to enter desired threshold in the Disease Prevalence box. Separate disease prevalence, score cutoff and utility threshold. Inverse net benefit is not literal tests required or alerts per detected case.
2. **psychopdaROC AUPRC omits the recall-zero segment.** Actual helper execution on scores `(0.1,0.2,0.8,0.9)` and truth `(N,N,P,P)` with direction `>=` returns **AUPRC=0.5 for a perfect classifier**. Threshold enumeration is observed scores only (`:1668`), integration `:1692–1696`. Consolidate onto a verified shared PR helper; enhancedROC already supplies a better starting implementation. Preserve separate trapezoidal PR area and AP names, and handle ties/endpoints/single-class cases explicitly.

## Concrete roadmap (proposed names, not implemented)

**P0 — repair semantics and numerical PR correctness.** Target enhancedROC existing `clinicalImpactTable`, `decisionImpactSummary`, `decisionImpactPlot`. Add `.a.yaml` `clinicalRiskThreshold` and `clinicalImpactCutoffs`, connect UI, leave `prevalence` solely population prevalence; state whether custom marker-scale cutoffs or probability-scale decision thresholds are used. Change `.b.R` to transport expected TP=N*p*Se, FP=N*(1-p)*(1-Sp), FN=N*p*(1-Se), TN=N*(1-p)*Sp at each locked cutoff; existing observed counts remain separately labeled. Rename inverse-NB output truthfully or omit it. Add `.r.yaml` `screeningWorkload` with `population_size`, `prevalence`, `cutoff`, `expected_tp/fp/fn/tn`, `alerts`, `ppv`, `alerts_per_true_positive`, `tests_per_detected_case`. Reuse this calculation in decisioncalculator, decision/decisioncompare. Repair psychopdaROC via shared PR helper and add `prAucMethod` if offering alternatives; verify claims in draft precisionrecall or disable unsupported methods.

**P1 — rare-disease scenarios.** Relax prevalence lower limit with explicit open-domain validation 0<p<1 and adequate numeric display precision. Add `targetPopulationSize` (e.g.10000), `prevalenceScenarios` (numeric-list String) and `showScreeningWorkload` across calculator/enhancedROC; UI section “Deployment prevalence and expected counts.” Distinguish fixed assumed prevalence from an estimated prevalence. Optional future `prevalenceEvents`/`prevalenceTotal` supports uncertainty propagation. Do not present expected fractional counts as observed counts. Retain conditional-on-Se/Sp transport caveat without claiming prevalence correction removes spectrum/site shifts.

**P1 — repeated-patient score inference and locked evaluation.** Add enhancedROC `.a.yaml` `patientID`, `resamplingUnit` (row/patient), optional `siteID`, `thresholdSource` (prespecified/development/exploratory), `modelVersion`, `predictionScale` (probability/score). Backend jointly resamples whole patients across all compared score columns, preserves thresholds/directions and reports invalid single-class draws, effective draws and unique-patient/event counts. Extend `precisionRecallTable` with AP/AUPRC CIs and method, add `thresholdPerformance` and `resamplingSummary`; extend `calibrationSummary` with CIs. UI exposes cluster fields only when requested; validate duplicate/missing IDs and explain estimand. pROC/boot/base R suffice; do not label DeLong or row-stratified CIs patient clustered.

**P2 — frozen external-site evaluation.** Extend reviewed production enhancedROC or promote modelval only after its own audit. `.a.yaml` `validationCohort`/`siteID`, `evaluationMode` (apparent/frozen_external), `thresholdSource`, `modelVersion`; `.b.R` evaluates supplied predictions per site without refitting/reoptimizing, jointly bootstrap within patient and prespecified site design; `.r.yaml` `sitePerformance` and `validationProvenance`: N patients/slides, events, prevalence, ROC AUC, AP, Se/Sp at locked cutoffs, PPV/NPV, calibration and CIs. Keep development, temporal/external and site results separate. UI “External validation” asks explicit model/threshold provenance. Do not substitute leave-one-center-out refitting for this task.

## Meaningful validation for future implementation

- PR: perfect and reversed classifier, all scores tied, ties in either row order, single positive, no positive, lower-is-positive; verify AP and trapezoid area separately against explicit definitions and established package output.
- Workload: fixed Se/Sp with prevalence 0.0001,0.001,0.01; Bayes PPV exactly equals expectedTP/(expectedTP+expectedFP); expected cells sum to N; score cutoff stays fixed when prevalence changes; utility threshold changes only net-benefit trade-off.
- Cluster: duplicated slides within each patient, unequal cluster sizes, paired missingness, rare/single-class bootstrap draws; reproducible seeds and patient-level external reference calculation.
- Site/calibration: locked model/threshold unchanged across cohorts; no-event site handled transparently; exact0/1 probabilities and separation; distinguish probability-scale calibration gap and logistic CITL; validate E/O and Brier denominators.
