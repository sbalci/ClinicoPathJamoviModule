### `chisqposttest` line 306

The post-hoc family includes a comparison that is not a comparison. .robustPairwiseTests() runs pairwise tests over BOTH dimensions unconditionally. When a dimension has exactly 2 levels its single 'pair' is the whole table, so that row IS the omnibus test. Verified by hand on a 3x2 table (grade x biomarker, the commonest pathology layout): the family is {G1vsG2, G1vsG3, G2vsG3, 'Neg vs Pos'}, the 4th row's raw p equals the omnibus p exactly (3.80e-4), and Bonferroni divides by m=4 instead of m=3, inflating EVERY genuine adjusted p by 4/3 (G2vsG3: 0.0185 correct vs 0.0247 reported). The repo's own test enshrines this: tests/testthat/test-chisqposttest-release-review.R:57 asserts .pairwiseComparisonCount(matrix(0,4,2)) == 7 (6 + 1).

**Fix:** Skip a dimension whose length is 2 when the OTHER dimension is also being partitioned, i.e. only emit pairwise comparisons for a dimension with >= 3 levels. Concretely, guard both loops with `if (length(row_names) >= 3)` / `if (length(col_names) >= 3)` and make .pairwiseComparisonCount() (line 214) use the same rule so m matches. Update the release-review test's expected counts (4x2 -> 6, 3x3 -> 6, 2x2 -> 0).

### `chisqposttest` line 264

Silent fallback to the invalid test. When testSelection is 'auto' and any expected count is < 5, Fisher's exact is requested precisely BECAUSE chi-square is not trustworthy; but `fisher_test <- try(stats::fisher.test(subtable), silent = TRUE)` sets fisher_test to NULL on failure and the code then falls through to `result$test_used <- 'Chi-square'`. On a 2xC subtable fisher.test() routinely fails with the FEXACT workspace error, which is a resource limit, not a data problem. The user gets the chi-square p-value the code just decided was unreliable, with no notice explaining that the exact test was attempted and abandoned. The same subtable can also hang for minutes inside fisher.test with no .checkpoint() reachable.

**Fix:** On try-error, retry once with `stats::fisher.test(subtable, simulate.p.value = TRUE, B = 1e5)` and label test_used 'Fisher's exact (Monte Carlo)'; only if that also fails, keep chi-square and raise private$.addNotice('STRONG_WARNING', ...) naming the comparison and stating that the exact test could not be computed.

### `benford` line 162

The order-of-magnitude gate `if (magnitude_range < 1)` is the wrong threshold and lets through precisely the regime that manufactures false alarms. 10^U data spanning an INTEGER number of decades is exactly Benford by construction, so a `< 1` cut-off tests the wrong boundary; the danger zone is a NON-INTEGER span between 1 and 2 decades, which passes silently with no warning. Simulated on perfectly clean 10^U data, n = 250, 2 digits, 300 reps: span 1.0 decades -> chi-square rejects 6.3% (fine), span 1.3 decades -> rejects 34.0%, span 2.0 -> 4.3%, span 3.0 -> 6.3%. The module's OWN documented example in benford.a.yaml:22 (histopathology$OverallTime) spans 1.30 decades, n = 248, and returns MAD = 0.0066, chi-square p = 6.2e-05, MAD/noise-floor = 1.31 -> concern_level 'Moderate' with recommendation to 'review data collection and entry procedures'. That is a narrow-range artefact reported to a pathologist as a data-quality finding, with zero warning shown.

**Fix:** Raise the hard threshold: warn (STRONG_WARNING, as now) whenever magnitude_range < 2, not < 1, and say in the notice that between 1 and 2 decades the leading-digit frequencies are dominated by where the range starts and ends rather than by Benford's Law, so the tests are not calibrated. Nigrini (2012) and Durtschi et al. (2004) both require several orders of magnitude. Then either replace the .a.yaml example variable with one that actually spans >= 2 decades, or leave OverallTime and let the new warning fire so the example demonstrates the guard.

### `benford` line 311

When the MAD label is unusable the whole verdict is taken from the chi-square p-value alone, on the strength of the claim at :253-256 ('The chi-square test does not have this problem - it is calibrated at every n') and the user-facing text at :303 and :337 ('the chi-square test, which is calibrated at any sample size'). That is false at digits = 3, and the failure is exactly in the operative range. Exactly-Benford data, 1500 reps: n = 150 -> P(p < .05) = 0.130 (SE 0.009), P(p < .01) = 0.061; n = 300 -> P(p < .05) = 0.095, P(p < .01) = 0.039. Nominal is 0.05 / 0.01. The 3-digit MAD label needs n > 2550, so for 100 <= n < ~600 with digits = 3 the entire 'Moderate'/'High concern' verdict runs at 2-3x its stated false-positive rate. Cause: 900 cells with minimum expected count 0.043 at n = 100 and 0.130 at n = 300 - every cell below 1. benford.analysis:::chisq.test.bfd applies no expected-count check at all, and neither does this code. The 2-digit default is also below Cochran's rule at typical clinical n (78 of 90 cells have expected < 5 on the documented example) though it stays empirically calibrated there.

**Fix:** Before letting chi-square drive the verdict, compute expected counts `n * bfd_df$benford.dist` and check them. Concretely: if `sum(n * benford.dist >= 5) / length(benford.dist) < 0.8`, emit a WARNING notice stating the proportion of cells with expected count below 5 and the minimum expected count, and do not raise concern_level above 'Moderate' on the chi-square alone. A simpler equivalent guard is to require n >= 5 * 10^digits (500 / 5000 / 50000) before treating the p-value as the sole basis, and otherwise recommend dropping to 1-digit analysis. Delete or correct the 'calibrated at every n' claim in the comment at :253-256 and in the strings at :303 and :337 - it is currently asserted to the user.

### `agepyramid` line 314

Unequal-width age bands are drawn as raw counts, so bar length is not comparable across bands. Four of the six shipped presets have unequal widths: pediatric (1,1,3,5,5,3,open), reproductive (15,5,5,5,5,5,5,5,open), geriatric (65,5,5,5,5,5,5,open) and lifecourse (5,10,10,20,20,10,10,open); arbitrary custom_breaks are unbounded in the same way. **Fix:** After breaks_seq is settled (around line 460), compute widths <- diff(breaks_seq[is.finite(breaks_seq)]); if length(unique(widths)) > 1, emit a WARNING notice stating that the bands cover different numbers of years so bar length and percentage are not comparable between bands, and naming the widest and narrowest. Optionally add a Bool option 'Count per year of age' that divides n by the band width for the plot (leaving the table as counts), which is the standard demographic remedy.

### `checkdata` line 510

The dropout heuristic tests the Wilson CI for the proportion of missing values landing in the last quarter against 0.5, but the null proportion under random missingness is 0.25 - the last quarter is a quarter of the rows (verified: n=120, last_quarter_start = round(90) = 90, rows 91-120 = 30/120 = 0.250). Requiring ci_low > 0.5 demands twice the null. Failure scenario: n_missing = 30 with 45% in the last quarter is an ~1.8x enrichment, but p_hat = 0.45 gives Wilson (0.29, 0.62) so ci_low < 0.5 and p_hat < 0.6 - neither branch fires and nothing is reported. Conversely the printed '95% CI: x%-y%' invites the reader to compare it to the 50% named in the same sentence, which is the wrong reference value.

**Fix:** Compute null_prop <- (n_total - last_quarter_start) / n_total and use it: `if (ci_low > null_prop)` for the likely-dropout branch (510) and `else if (dropout_prop > 1.5 * null_prop)` for the possible branch (515). Print the null in the message: '%.1f%% of missing values fall in the last quarter of rows; %.1f%% expected if missingness were unrelated to row position'.

### `outlierdetection` line 1690

.expected_flag_rate() (L1044) returns the ASYMPTOTIC tail probability 2*pnorm(-z) (L1049) / 2*pnorm(-(0.6745+1.349*k)) (L1053), and the Exclusion Recommendations panel presents it as what 'a normally distributed variable would be expected to produce ... by chance alone', then instructs the reader that 'the comparison between those two numbers, not the observed rate on its own, is what indicates whether the data carry more extreme values than the threshold anticipates.' The finite-sample rate is materially higher at clinical sample sizes. Simulation on clean N(0,1), 3 variables, 400 replicates: robust Z at 3.29 gives 0.95% observed at n=50 vs 0.30% predicted (3.2x), 0.58% at n=100, 0.43% at n=200, converging only by n=2000 (0.32%). IQR at 1.7 gives 2.19% at n=50 vs 0.90% predicted (2.4x), 1.53% at n=100, 1.18% at n=200. Robust Z is the module default and MAD has ARE 0.37, so its finite-sample tail is fat. A pathologist with a 50-case series and clean data is therefore told there is a 3-fold excess of extreme values, and the panel's own bullet then attributes an excess to 'heavier tails ..., a mixture of distinct subgroups, or data errors'. (Standard Z errs the other way: 0.11% at n=50 vs 0.30% predicted, because the outlier inflates its own SD.)

**Fix:** Replace the closed form with a parametric bootstrap at the ACTUAL n and method - 200 replicates of rnorm(n) through the same flag_one() already written in .univariate_drivers() takes single-digit milliseconds and is exact by construction, including for eti/hdi where the function currently returns NULL. Cheaper alternative if you do not want the simulation: keep the formula, but only print the number when nrow(data) >= 500, and below that say the chance-expected rate at this sample size is materially higher than the large-sample value and no benchmark is offered.
