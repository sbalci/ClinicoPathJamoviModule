# Win Ratio analysis — implementation summary

**Analysis added:** `winratio` — *Win Ratio for Hierarchical Composite Endpoints*
**Date:** 2026-07-10 · **Placement:** menuGroup `SurvivalD` → menuSubgroup *Specialized Survival Methods*

Selected as the top Tier-1 gap from `development-ideas/analysis-gap-review-2026.md`
(win ratio existed only as a helper inside `stagemigration`, with no standalone endpoint analysis).

## Files created
| File | Purpose |
|------|---------|
| `jamovi/winratio.a.yaml` | Options: group + reference level, primary TTE endpoint, optional secondary TTE endpoint, optional continuous tiebreaker, CI method (analytic/bootstrap), display toggles. |
| `jamovi/winratio.r.yaml` | Results: main table (win ratio / win odds / net benefit), pairwise counts, endpoint-contribution table, win/loss/tie plot, summary + methodology HTML. |
| `jamovi/winratio.u.yaml` | UI layout (VariableSupplier + LevelSelectors + collapse boxes). |
| `R/winratio.b.R` | Backend `winratioClass` (R6). |
| `jamovi/00refs.yaml` | Added `pocock2012winratio`, `dong2016winratio`. |
| `data-raw/winratio_test_data.R` + `data/winratio_test_data.csv` | Two-arm composite test dataset (death → hospitalization → 6MWD change). |
| `tests/testthat/test-winratio.R` | Two tests: primary-only and 3-tier composite. |

## Method
- Every index-group subject is compared with every reference-group subject; each pair is a
  **win / loss / tie** decided by the first endpoint (in priority order) able to order it.
- Time-to-event rule: a pair is decided only when one subject's event time is exceeded by the
  other's follow-up, so censored-unorderable pairs stay ties (standard Pocock 2012 unmatched WR).
- Reports **win ratio** (wins/losses), **win odds** (ties split), **net benefit** ((W−L)/total).
- **Analytic CI**: variance of log(WR) from per-subject win/loss proportions, Dong et al. (2016).
- **Bootstrap CI**: subject-level resampling within each arm.

## Validation performed (managed R 4.5.3, engine mirrored outside jamovi)
- Analytic point estimate & CI reproduced by a 400-rep subject-level bootstrap
  (WR 1.635 vs bootstrap median 1.637; CI [1.20,2.23] vs [1.18,2.28]).
- Direction/magnitude consistent with Cox `1/HR` (1.55) on the same data.
- 3-tier hierarchy verified: ties fall to 0 as lower-priority endpoints break them;
  endpoint-contribution counts sum correctly to W+L.
- No-losses edge case returns WR = Inf with SE/CI/p set to NA (guarded).

# Fragility Index — implementation summary

**Analysis added:** `fragilityindex` — *Fragility Index for Dichotomous Outcomes*
**Date:** 2026-07-10 · **Placement:** menuGroup `meddecideD` → menuSubgroup *Study Design*

Second Tier-1 gap from `analysis-gap-review-2026.md` (absent from the catalog entirely).

## Files created
| File | Purpose |
|------|---------|
| `jamovi/fragilityindex.{a,r,u}.yaml` | Options (summary counts OR raw group+outcome, Fisher/chi-square, alpha), results (2x2 table, FI/FQ table, reversal trajectory, p-value trajectory plot), UI. |
| `R/fragilityindex.b.R` | `fragilityindexClass` R6 backend. |
| `jamovi/00refs.yaml` | Added `walsh2014fragility`. |
| `data-raw/fragilityindex_test_data.R` + `data/fragilityindex_test_data.csv` | Raw 2x2 example (10/100 vs 25/100). |
| `tests/testthat/test-fragilityindex.R` | Summary input, reverse index, raw-data input. |

## Method
- Greedy iterative outcome reversal: at each step switch the one patient outcome that moves
  the p-value fastest across `alpha`; count switches (Walsh et al. 2014).
- **Fragility Index** for significant results (reversals toward non-significance);
  **reverse fragility index** for non-significant results (reversals toward significance).
- **Fragility Quotient** = FI / total N. Fisher's exact (default) or chi-square at each step.

## Validation (managed R 4.5.3)
- Greedy FI matched an exhaustive brute-force minimum (FI = 4 for 10/100 vs 25/100, p0 = 0.0085).
- Reverse FI = 5 for the non-significant 18/100 vs 25/100 case (p0 = 0.30).
- Chi-square gives FI = 5 (correctly differs from Fisher's exact, which is more conservative).

# Interrupted Time Series — implementation summary

**Analysis added:** `interruptedtimeseries` — *Interrupted Time Series Analysis*
**Date:** 2026-07-10 · **Placement:** menuGroup `ClinicoPathD` → menuSubgroup *Statistical Tests*

Third Tier-1 gap (absent; distinct from `labcontrolcharts`, which is SPC not causal ITS).

## Files created
| File | Purpose |
|------|---------|
| `jamovi/interruptedtimeseries.{a,r,u}.yaml` | Options (time, outcome, intervention time, Newey-West HAC + lag, counterfactual, predict-at), results (coefficient table, effect table, DW diagnostics, plot), UI. |
| `R/interruptedtimeseries.b.R` | `interruptedtimeseriesClass` R6 backend. |
| `jamovi/00refs.yaml` | Added `wagner2002its`, `bernal2017its`. |
| `DESCRIPTION` | Added `sandwich`, `lmtest` to Imports. |
| `data-raw/interruptedtimeseries_test_data.R` + `data/interruptedtimeseries_test_data.csv` | Monthly QI series, intervention at month 25. |
| `tests/testthat/test-interruptedtimeseries.R` | Segmented fit + out-of-range intervention guard. |

## Method
- Segmented regression `Y ~ time + post + time_after` (Wagner 2002; Bernal 2017), estimating
  baseline level & trend, level change, and trend change.
- **Newey-West HAC** standard errors for autocorrelation (via `sandwich`/`lmtest`), with a
  graceful OLS fallback; **Durbin-Watson** residual-autocorrelation diagnostic.
- Optional counterfactual projection and absolute/relative effect at a chosen time point.

## Validation (managed R 4.5.3)
- Recovered simulated parameters: level change −13.6 (true −12), trend change +0.83 (true +0.8),
  baseline trend 0.50 (true 0.5) on a clean simulation.
- HAC standard errors and Durbin-Watson diagnostic confirmed working with `sandwich`/`lmtest`.
